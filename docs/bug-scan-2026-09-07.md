## Fix details

### Webhook delivery fails closed on unresolved hostnames

When private targets are forbidden, an empty hostname resolution now fails that
attempt instead of issuing an unpinned hostname request. A later retry validates
and pins its own resolution. Literal IP validation and the operator's explicit
private-target opt-in are preserved. The regression checks failure/cursor state
and a subsequent successfully pinned retry.

### Rollout occupancy is not serving availability

Pending, leased, and dispatching replacements no longer justify stopping a
running old replica. Already-cancelling replicas do not provide availability.
Non-running old replicas may be retired without consuming the running-replica
allowance. This uses workload state; it does not introduce application-readiness
semantics or promise that every RUNNING application is healthy.

### Cell updates account for the landed elastic member

For per-worker elastic leases, `upsert_cell` uses the existing cell's worker
count rather than the full workload width. Tests cover memory and SQLite, both
an unchanged cell update and rejection of a genuinely undersized allocation.
This repairs a separate path missed by the prior scheduler conversion fix.

### Budget-aware fallback for elastic packs

The ordinary preferred-pack selection remains unchanged. Only if that pack
fails budget validation, a second search retains the cheapest subset for each
worker total and cell count. It selects the fewest-cell affordable exact pack,
rechecking all ancestor budgets and resource-hour limits. Resource-hours for
an exact worker total do not depend on which cells provide it.
